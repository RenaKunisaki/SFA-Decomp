# Cross-Version Progress

The project reports progress for five retail DOLs while keeping `GSAE01` (EN
v1.0) as the default matching target:

- `GSAE01`
- `GSAE01_rev1`
- `GSAJ01`
- `GSAP01` (PAL rev 0)
- `GSAP01_rev1` (PAL rev 1)

The non-default splits are coherent whole-TU projections from the active EN
config. `tools/version_progress.py` normalizes address-bearing PowerPC
instructions and relocated data pointers, finds unique binary contexts, and
uses stable address-delta corridors to map every owned section together. A TU
is emitted only when all of its text, metadata, data, and BSS boundaries are
legal in the target. Target function boundaries remain authoritative; canonical
EN names are assigned by unique body match or, within a coherent range, by
ordinal when the function counts agree.

Uncertain corridors remain decomp-toolkit autogenerated units and stay in the
report denominator. No version-specific source guards are introduced. Equal-
size non-code ranges receive the canonical EN symbols; size-drift ranges retain
the target's symbols and are accepted only when those symbols do not cross an
inferred boundary.

These projected targets are report-only for now. They do not yet assign enough
data and relocation-coupled sections to relink their retail DOLs, so
`--matching` is intentionally rejected for non-EN versions. Their linked
percentage remains zero. EN v1.0 remains the only strict checksum target.

Regenerate a target after the EN splits change:

```sh
python tools/version_progress.py GSAE01_rev1 --write
python tools/version_progress.py GSAJ01 --write
python tools/version_progress.py GSAP01 --write
python tools/version_progress.py GSAP01_rev1 --write
```

Then configure and build its report normally:

```sh
python configure.py --version GSAJ01
ninja all_source progress build/GSAJ01/report.json
```

After generating and validating a report, record its exact source objects:

```sh
python tools/version_progress.py GSAJ01 --write-matching
```

The generated `matching_units.txt` is loaded by `configure.py` and augments the
existing `MatchingFor` result for that version. Only objects whose applicable
code and data scores are all 100% are listed. `symbol_mappings.json` remains a
fallback for the few canonical-name conflicts; most pairing is encoded directly
in the target symbol file. The default EN build and its completion flags are
unchanged.
