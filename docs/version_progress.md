# Cross-Version Progress

The project reports progress for four retail DOLs while keeping `GSAE01` (EN
v1.0) as the default matching target:

- `GSAE01`
- `GSAE01_rev1`
- `GSAJ01`
- `GSAP01`

The non-default splits are conservative projections from the active EN config.
`tools/version_progress.py` normalizes address-bearing PowerPC instructions,
finds function bodies that are unique in both DOLs, and assigns a shared source
unit only when both text boundaries are anchored and the function count is
unchanged. Units with coupled exception or constructor metadata are skipped.

Uncertain code and all unported data remain decomp-toolkit autogenerated units.
They are still included in the report denominator and count as unmatched. This
makes the initial cross-version percentages intentionally low but prevents
speculative boundaries from inflating progress.

These projected targets are report-only for now. They do not yet assign enough
data and relocation-coupled sections to relink their retail DOLs, so
`--matching` is intentionally rejected for non-EN versions. Their linked
percentage remains zero. EN v1.0 remains the only strict checksum target.

Regenerate a target after the EN splits change:

```sh
python tools/version_progress.py GSAE01_rev1 --write
python tools/version_progress.py GSAJ01 --write
python tools/version_progress.py GSAP01 --write
```

Then configure and build its report normally:

```sh
python configure.py --version GSAJ01
ninja all_source progress build/GSAJ01/report.json
```

The generated `symbol_mappings.json` files map target function symbols to the
canonical EN source symbols for objdiff. They affect comparison only; the
default EN build and its completion flags are unchanged.
